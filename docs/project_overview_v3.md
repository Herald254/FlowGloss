# 🚀 FlowGloss 项目架构设计规范 (V3.0)

**项目定位**：一款基于事件驱动、增量识别与本地认知模型的桌面 AI 学习助手。
**核心理念**：减少认知负荷，通过非侵入式交互，实现“即读即懂”的沉浸式学习体验。

---

## 一、 系统全景架构
FlowGloss 在 V2.0 的基础上，引入**深度学习优化**和**个性化推荐**，实现真正的自适应学习系统。

### 1. 进程规划（保持V2.0架构）
* **Main Process (UI & Registry)**: 负责界面渲染、系统托盘及各进程间的状态同步。
* **Vision Process (Compute)**: 独立进程，负责截图、OpenCV 图像处理及本地 GPU 驱动的 OCR 推理。
* **Cognition Process (Inference)**: 独立进程，运行本地 NER 模型（GLiNER），与 Vision 进程共享 GPU 显存池。

### 2. V3.0 新增特性
* **深度学习优化**：引入SBERT词向量计算和FAISS高效检索，提升语义关联准确性
* **个性化推荐**：基于用户学习历史和偏好，动态调整推荐策略
* **自适应权重**：使用强化学习算法动态优化双轴难度计算的权重
* **时间衰减机制**：长期未接触的词汇，掌握度会缓慢衰减，需要重新学习
* **知识图谱可视化**：提供用户知识网络的可视化界面，帮助用户了解自己的学习进度

## 二、 核心模块技术详述（V3.0升级）

### 1. 事件触发模块 (`core/monitor`) [V2.0基础 + 深度优化]
* **技术简介**：利用 `pynput` 构建的底层系统钩子。
* **系统作用**：监听全局鼠标滚轮与键盘翻页，结合行为数据和深度学习模型判断阅读状态。
* **关键逻辑**：
    * **防抖算法**：设置 `1.0s` 稳定阈值。当用户停止滚动超过 1 秒时，才视为进入阅读态，触发后续流程。
    * **悬停检测**：记录鼠标实时坐标。当 OCR 提取出候选词边界框（BBox）时，检测鼠标是否在该 BBox 内停留 > 800ms
    * **阅读节奏**：统计近 5 秒滚轮滚动频率。如果频率突然断崖式下降，判定为阅读受阻，触发行为加分（Behavior Bonus）
    * **轨迹分析**：使用深度学习模型分析鼠标移动轨迹的平滑度，不规则的抖动可能表示困惑
* **线程位置**：**独立守护线程**，确保 0 延迟响应。

### 2. 视觉识别模块 (`core/vision`) [V2.0基础 + 深度学习优化]
* **技术简介**：集成 `mss` 截图与 `PaddleOCR` (GPU 加速版) + FastText语种检测 + 深度学习模型。
* **系统作用**：将屏幕像素转化为带位置信息的结构化文本，自动识别语言类型，并使用深度学习模型优化识别结果。
* **核心细节**：
    * **图像差分 (Image Diff)**：使用 `cv2.absdiff` 对比前后帧。若变化率低于 `5%`，直接熔断，不执行 OCR，极大节省 GPU 资源。
    * **增量识别**：仅对识别出的“新增区域”进行文本提取，减少重复计算。
    * **多语种检测**：使用FastText预训练模型，在10ms内完成语种识别，支持中英混合、多语言混合场景
    * **深度学习优化**：使用深度学习模型对OCR结果进行后处理，提升识别准确率
* **外界调用**：`capture_and_process() -> List[TextBlock]`。
* **运行位置**：**Vision 子进程**。

### 3. 认知过滤模块 (`core/cognition`) [V2.0基础 + 深度学习优化]
* **技术简介**：本地轻量级命名实体识别 (GLiNER-base) + SBERT词向量计算 + FAISS高效检索。
* **系统作用**：从文本流中筛选出术语、专有名词、缩写，并使用深度学习模型进行语义关联。
* **过滤机制**：
    * **已知过滤**：对比本地 `KnowledgeDB`。如果词汇属于“用户已掌握”，直接忽略。
    * **重要性排序**：根据词频与语境相关度，只根据用户设定值选取最核心的一定数量生词进行解释。
    * **语义关联**：使用SBERT计算词向量间的余弦相似度，构建精确的语义网络
    * **高效检索**：使用FAISS索引 + HNSW算法，实现毫秒级语义相似度查询
* **外界调用**：`extract_entities(text) -> List[Term]`。
* **运行位置**：**Cognition 子进程**。

### 4. 解释生成模块 (`core/glossary`) [V2.0基础 + 深度学习优化]
* **技术简介**：基于异步 `httpx` 的 API 客户端，对接高性能云端大模型。
* **系统作用**：根据生词与上下文生成 50~100 字的精准解释。
* **技术亮点**：
    * **流式回传**：支持 SSE 协议，文字逐个蹦出，降低用户感知延迟。
    * **动态提示词工程**：根据词汇难度、语种和用户偏好，动态调整提示词模板。例如：“请以 Python 专家的身份，为 [Context] 中的词汇 [Term] 提供易懂的定义”
    * **个性化解释**：使用深度学习模型分析用户历史偏好，动态调整解释的详细程度和风格
    * **自适应权重**：使用强化学习算法动态优化双轴难度计算的权重
* **运行位置**：**异步 I/O 线程池**。

### 5. 知识数据库 (`data/database`) [V2.0基础 + 深度学习优化]
* **技术简介**：`SQLite3` 持久化层 + 高级语义网络 + 知识图谱可视化。
* **系统作用**：存储用户“知识图谱”，实现个性化记忆、知识关联和时间衰减。
* **核心字段**：`word_id`, `mastery_level` (-1:简单, 0:未知, 1:模糊), `last_seen_context`, `frequency`, `semantic_score`, `last_review_time`。
* **新增功能**：
    * **语义关联**：存储词汇间的精确相似度关系
    * **领域传播**：在同一个技术领域内，相关概念的知识掌握度会相互影响
    * **时间衰减**：长期未接触的词汇，掌握度会缓慢衰减，需要重新学习
    * **知识图谱可视化**：提供用户知识网络的可视化界面，帮助用户了解自己的学习进度
* **线程位置**：**主进程**，通过线程安全队列接收更新。

## 三、 现代化 UI 设计 (`ui/overlay`) [V3.0升级]

FlowGloss 追求**“空气感”**交互，不干扰阅读，并根据用户理解程度和偏好自适应调整。

* **技术选型**：`PySide6` + `PyQt-Fluent-Widgets`。
* **视觉特征**：
    * **亚克力 (Acrylic) 效果**：窗口背景半透明并模糊处理，透出文档底色。
    * **悬浮动画**：卡片采用弹性淡入动画（Ease-out）。
    * **鼠标穿透 (Click-through)**：默认状态不干扰鼠标对网页的滚动；当光标进入卡片热区时，激活反馈按钮。
* **自适应交互**：
    * **确信不懂**（D > 0.9）：正常弹出卡片，完整显示解释
    * **不确定懂不懂**（0.7 < D ≤ 0.9）：仅在文字下方渲染一层微弱的半透明色块，鼠标移入后才展开完整卡片
    * **可能懂了**（0.5 < D ≤ 0.7）：仅在鼠标悬停时显示简短提示
    * **应该懂了**（D ≤ 0.5）：完全不显示，避免干扰
* **个性化交互**：
    * **学习进度可视化**：提供知识图谱的可视化界面，展示用户的学习进度和知识网络
    * **个性化设置**：允许用户自定义交互强度、解释风格等偏好
* **反馈交互**：
    > 提供三个极简 Icon：
    > * **[-]** 标记为“已掌握”，永久隐藏该词。
    > * **[=]** 标记为“一般”，保持现状。
    > * **[+]** 标记为“需巩固”，未来增加出现频率。

## 四、 性能与成本优化策略（V3.0增强）

| 策略 | 实现方案 | 预期效果 |
| :--- | :--- | :--- |
| **计算熔断** | 图像对比发现画面静止时，0 计算量。 | 降低待机功耗。 |
| **内存隔离** | 核心模型在子进程加载，主界面永不卡顿。 | 维持 120fps 丝滑体验。 |
| **显存调度** | 限制 OCR 和 NER 进程的显存占比（各 30%）。 | 允许用户同时运行开发环境或轻度游戏。 |
| **缓存机制** | 对于 24 小时内请求过的同一领域词汇，直接读本地缓存。 | 节省 40% 以上的 API 调用开销。 |
| **语义扩散** | 掌握一词，自动降低相关词汇的显示优先级。 | 减少50%的重复解释请求。 |
| **多语种优化** | 根据语种调用对应的词频库和NER模型。 | 提升多语言场景的识别准确率。 |
| **深度学习优化** | 使用SBERT和FAISS进行精确的语义关联和高效检索。 | 提升语义关联准确性，降低计算延迟。 |
| **个性化推荐** | 基于用户学习历史和偏好，动态调整推荐策略。 | 提升推荐相关性，减少无关干扰。 |
| **时间衰减机制** | 长期未接触的词汇，掌握度会缓慢衰减。 | 确保知识网络的时效性，避免过时信息。 |

## 六、 V3.0 高级特性

### 1. 数学模型详解

#### 1.1 双轴难度计算（V3.0增强）

D = (L × w₁ + K × w₂) × (1 + Behavior_Bonus) × (1 + Personalization_Factor)

其中：
- L (Language Difficulty): 语言难度，基于词频库计算
- K (Knowledge Depth): 知识深度，基于Wikidata权重计算
- w₁, w₂: 动态权重，根据用户反馈和强化学习算法动态调整
- Behavior_Bonus: 行为加分，基于鼠标轨迹和阅读节奏
- Personalization_Factor: 个性化因子，基于用户学习历史和偏好

#### 1.2 语义相似度计算（V3.0增强）

Similarity = cos(word₁, word₂) × (1 + Context_Relevance)

使用SBERT计算词向量间的余弦相似度，并考虑上下文相关性，用于知识图谱扩散。

### 2. 算法优化策略（V3.0增强）

| 优化点 | 实现方案 | 预期效果 |
| :--- | :--- | :--- |
| **快速语种检测** | FastText预训练模型 + 缓存机制 | 10ms内完成语种识别 |
| **高效向量检索** | FAISS索引 + HNSW算法 | 毫秒级语义相似度查询 |
| **增量图谱更新** | 只更新受影响的节点和边 | 降低图谱维护成本 |
| **自适应权重调整** | 强化学习算法动态优化 $w_1, w_2$ | 提升推荐准确性 |
| **个性化推荐** | 基于用户学习历史和偏好的深度学习模型 | 提升推荐相关性，减少无关干扰 |
| **时间衰减机制** | 长期未接触的词汇，掌握度会缓慢衰减 | 确保知识网络的时效性，避免过时信息 |
