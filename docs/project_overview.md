# 🚀 FlowGloss 项目架构设计规范 (V1.0)

**项目定位**：一款基于事件驱动、增量识别与本地认知模型的桌面 AI 学习助手。
**核心理念**：减少认知负荷，通过非侵入式交互，实现“即读即懂”的沉浸式学习体验。

---

## 一、 系统全景架构

FlowGloss 采用 **多进程 + 异步 I/O** 混合架构，以规避 Python GIL 锁对性能的限制，并充分发挥 **RTX 50 系列显卡** 的并行计算能力。

### 1. 进程规划
* **Main Process (UI & Registry)**: 负责界面渲染、系统托盘及各进程间的状态同步。
* **Vision Process (Compute)**: 独立进程，负责截图、OpenCV 图像处理及本地 GPU 驱动的 OCR 推理。
* **Cognition Process (Inference)**: 独立进程，运行本地 NER 模型（GLiNER），与 Vision 进程共享 GPU 显存池。

---

## 二、 核心模块技术详述

### 1. 事件触发模块 (`core/monitor`)
* **技术简介**：利用 `pynput` 构建的底层系统钩子。
* **系统作用**：监听全局鼠标滚轮与键盘翻页。
* **关键逻辑**：
    * **防抖算法**：设置 `1.0s` 稳定阈值。当用户停止滚动超过 1 秒时，才视为进入阅读态，触发后续流程。
* **线程位置**：**独立守护线程**，确保 0 延迟响应。

### 2. 视觉识别模块 (`core/vision`)
* **技术简介**：集成 `mss` 截图与 `PaddleOCR` (GPU 加速版)。
* **系统作用**：将屏幕像素转化为带位置信息的结构化文本。
* **核心细节**：
    * **图像差分 (Image Diff)**：使用 `cv2.absdiff` 对比前后帧。若变化率低于 `5%`，直接熔断，不执行 OCR，极大节省 GPU 资源。
    * **增量识别**：仅对识别出的“新增区域”进行文本提取，减少重复计算。
* **外界调用**：`capture_and_process() -> List[TextBlock]`。
* **运行位置**：**Vision 子进程**。

### 3. 认知过滤模块 (`core/cognition`)
* **技术简介**：本地轻量级命名实体识别 (GLiNER-base)。
* **系统作用**：从文本流中筛选出术语、专有名词、缩写。
* **过滤机制**：
    * **已知过滤**：对比本地 `KnowledgeDB`。如果词汇属于“用户已掌握”，直接忽略。
    * **重要性排序**：根据词频与语境相关度，只选取最核心的 1~3 个生词进行解释。
* **外界调用**：`extract_entities(text) -> List[Term]`。
* **运行位置**：**Cognition 子进程**。

### 4. 解释生成模块 (`core/glossary`)
* **技术简介**：基于异步 `httpx` 的 API 客户端，对接高性能云端大模型。
* **系统作用**：根据生词与上下文生成 50~100 字的精准解释。
* **技术亮点**：
    * **流式回传**：支持 SSE 协议，文字逐个蹦出，降低用户感知延迟。
    * **提示词工程**：动态注入上下文。例如：“请以 Python 专家的身份，为 [Context] 中的词汇 [Term] 提供易懂的定义”。
* **运行位置**：**异步 I/O 线程池**。

### 5. 知识数据库 (`data/database`)
* **技术简介**：`SQLite3` 持久化层。
* **系统作用**：存储用户“知识图谱”。
* **核心字段**：`word_id`, `mastery_level` (-1:简单, 0:未知, 1:模糊), `last_seen_context`, `frequency`。
* **线程位置**：**主进程**，通过线程安全队列接收更新。

## 三、 现代化 UI 设计 (`ui/overlay`)

FlowGloss 追求**“空气感”**交互，不干扰阅读。

* **技术选型**：`PySide6` + `PyQt-Fluent-Widgets`。
* **视觉特征**：
    * **亚克力 (Acrylic) 效果**：窗口背景半透明并模糊处理，透出文档底色。
    * **悬浮动画**：卡片采用弹性淡入动画（Ease-out）。
    * **鼠标穿透 (Click-through)**：默认状态不干扰鼠标对网页的滚动；当光标进入卡片热区时，激活反馈按钮。
* **反馈交互**：
    > 提供三个极简 Icon：
    > * **[-]** 标记为“已掌握”，永久隐藏该词。
    > * **[=]** 标记为“一般”，保持现状。
    > * **[+]** 标记为“需巩固”，未来增加出现频率。

## 四、 性能与成本优化策略

| 策略 | 实现方案 | 预期效果 |
| :--- | :--- | :--- |
| **计算熔断** | 图像对比发现画面静止时，0 计算量。 | 降低待机功耗。 |
| **内存隔离** | 核心模型在子进程加载，主界面永不卡顿。 | 维持 120fps 丝滑体验。 |
| **显存调度** | 限制 OCR 和 NER 进程的显存占比（各 30%）。 | 允许用户同时运行开发环境或轻度游戏。 |
| **缓存机制** | 对于 24 小时内请求过的同一领域词汇，直接读本地缓存。 | 节省 40% 以上的 API 调用开销。 |

---

## 五、 MVP 开发路线图

1.  **Phase 1 (底层打通)**：实现全局监听 -> 截图 -> PaddleOCR 的基本链路，通过控制台输出文字。
2.  **Phase 2 (本地模型集成)**：接入 GLiNER，实现从一段话中精准“抠”出生词。
3.  **Phase 3 (UI 与云端)**：构建亚克力悬浮窗，接入 API 实现流式显示，完成数据库闭环。
4.  **Phase 4 (优化)**：加入图像差分算法与鼠标穿透逻辑。

---

> **结语**：FlowGloss 不仅仅是一个 OCR 翻译器，它是一个运行在本地显卡上的“认知伴侣”。它通过对屏幕内容的深度解构，为用户构建起一个无形的、自动生长的知识网络。
