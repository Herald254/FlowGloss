# 🚀 FlowGloss 项目架构设计规范 (V2.0)

**项目定位**：一款基于事件驱动、增量识别与本地认知模型的桌面 AI 学习助手。
**核心理念**：减少认知负荷，通过非侵入式交互，实现“即读即懂”的沉浸式学习体验。

---

## 一、 系统全景架构

FlowGloss 在 V1.0 的基础上，引入**行为数据挖掘**和**多语种支持**，实现更智能的触发和更精准的识别。

### 1. 进程规划（保持V1.0架构）
* **Main Process (UI & Registry)**: 负责界面渲染、系统托盘及各进程间的状态同步。
* **Vision Process (Compute)**: 独立进程，负责截图、OpenCV 图像处理及本地 GPU 驱动的 OCR 推理。
* **Cognition Process (Inference)**: 独立进程，运行本地 NER 模型（GLiNER），与 Vision 进程共享 GPU 显存池。

### 2. V2.0 新增特性
* **行为校验**：引入鼠标轨迹分析和阅读节奏检测，主观判断阅读困惑程度
* **多语种检测**：集成FastText，支持中英混合、多语言混合场景
* **语义关联**：构建基础语义网络，实现“掌握一词，精通一类”的效果
* **自适应难度**：基于语言难度和知识深度的双轴评分系统

## 二、 核心模块技术详述（V2.0升级）

### 1. 事件触发模块 (`core/monitor`) [V1.0基础 + 行为校验]
* **技术简介**：利用 `pynput` 构建的底层系统钩子。
* **系统作用**：监听全局鼠标滚轮与键盘翻页，结合行为数据判断阅读状态。
* **关键逻辑**：
    * **防抖算法**：设置 `1.0s` 稳定阈值。当用户停止滚动超过 1 秒时，才视为进入阅读态，触发后续流程。
    * **悬停检测**：记录鼠标实时坐标。当 OCR 提取出候选词边界框（BBox）时，检测鼠标是否在该 BBox 内停留 > 800ms
    * **阅读节奏**：统计近 5 秒滚轮滚动频率。如果频率突然断崖式下降，判定为阅读受阻，触发行为加分（Behavior Bonus）
* **线程位置**：**独立守护线程**，确保 0 延迟响应。

### 2. 视觉识别模块 (`core/vision`) [V1.0基础 + 多语种检测]
* **技术简介**：集成 `mss` 截图与 `PaddleOCR` (GPU 加速版) + FastText语种检测。
* **系统作用**：将屏幕像素转化为带位置信息的结构化文本，自动识别语言类型。
* **核心细节**：
    * **图像差分 (Image Diff)**：使用 `cv2.absdiff` 对比前后帧。若变化率低于 `5%`，直接熔断，不执行 OCR，极大节省 GPU 资源。
    * **增量识别**：仅对识别出的“新增区域”进行文本提取，减少重复计算。
    * **多语种检测**：使用FastText预训练模型，在10ms内完成语种识别，支持中英混合、多语言混合场景
* **外界调用**：`capture_and_process() -> List[TextBlock]`。
* **运行位置**：**Vision 子进程**。

### 3. 认知过滤模块 (`core/cognition`) [V1.0基础 + 语义关联]
* **技术简介**：本地轻量级命名实体识别 (GLiNER-base) + 基础语义网络。
* **系统作用**：从文本流中筛选出术语、专有名词、缩写，并关联相关知识。
* **过滤机制**：
    * **已知过滤**：对比本地 `KnowledgeDB`。如果词汇属于“用户已掌握”，直接忽略。
    * **重要性排序**：根据词频与语境相关度，只根据用户设定值选取最核心的一定数量生词进行解释。
    * **语义关联**：当用户标记某个词为“太简单”时，通过词向量计算相似度，自动给相关词汇增加预判分
* **外界调用**：`extract_entities(text) -> List[Term]`。
* **运行位置**：**Cognition 子进程**。

### 4. 解释生成模块 (`core/glossary`) [V1.0基础 + 动态Prompt]
* **技术简介**：基于异步 `httpx` 的 API 客户端，对接高性能云端大模型。
* **系统作用**：根据生词与上下文生成 50~100 字的精准解释。
* **技术亮点**：
    * **流式回传**：支持 SSE 协议，文字逐个蹦出，降低用户感知延迟。
    * **动态提示词工程**：根据词汇难度和语种，动态调整提示词模板。例如：“请以 Python 专家的身份，为 [Context] 中的词汇 [Term] 提供易懂的定义”
    * **个性化解释**：根据用户历史偏好，调整解释的详细程度和风格
* **运行位置**：**异步 I/O 线程池**。

### 5. 知识数据库 (`data/database`) [V1.0基础 + 语义图谱]
* **技术简介**：`SQLite3` 持久化层 + 基础语义网络。
* **系统作用**：存储用户“知识图谱”，实现个性化记忆和知识关联。
* **核心字段**：`word_id`, `mastery_level` (-1:简单, 0:未知, 1:模糊), `last_seen_context`, `frequency`, `semantic_score`。
* **新增功能**：
    * **语义关联**：存储词汇间的相似度关系
    * **领域传播**：在同一个技术领域内，相关概念的知识掌握度会相互影响
* **线程位置**：**主进程**，通过线程安全队列接收更新。

## 三、 现代化 UI 设计 (`ui/overlay`) [V2.0升级]

FlowGloss 追求**“空气感”**交互，不干扰阅读，并根据用户理解程度自适应调整。

* **技术选型**：`PySide6` + `PyQt-Fluent-Widgets`。
* **视觉特征**：
    * **亚克力 (Acrylic) 效果**：窗口背景半透明并模糊处理，透出文档底色。
    * **悬浮动画**：卡片采用弹性淡入动画（Ease-out）。
    * **鼠标穿透 (Click-through)**：默认状态不干扰鼠标对网页的滚动；当光标进入卡片热区时，激活反馈按钮。
* **自适应交互**：
    * **确信不懂**（D > 0.9）：正常弹出卡片，完整显示解释
    * **不确定懂不懂**（0.7 < D ≤ 0.9）：仅在文字下方渲染一层微弱的半透明色块，鼠标移入后才展开完整卡片
    * **可能懂了**（0.5 < D ≤ 0.7）：仅在鼠标悬停时显示简短提示
    * **应该懂了**（D ≤ 0.5）：完全不显示，避免干扰
* **反馈交互**：
    > 提供三个极简 Icon：
    > * **[-]** 标记为“已掌握”，永久隐藏该词。
    > * **[=]** 标记为“一般”，保持现状。
    > * **[+]** 标记为“需巩固”，未来增加出现频率。

## 四、 性能与成本优化策略（V2.0增强）

| 策略 | 实现方案 | 预期效果 |
| :--- | :--- | :--- |
| **计算熔断** | 图像对比发现画面静止时，0 计算量。 | 降低待机功耗。 |
| **内存隔离** | 核心模型在子进程加载，主界面永不卡顿。 | 维持 120fps 丝滑体验。 |
| **显存调度** | 限制 OCR 和 NER 进程的显存占比（各 30%）。 | 允许用户同时运行开发环境或轻度游戏。 |
| **缓存机制** | 对于 24 小时内请求过的同一领域词汇，直接读本地缓存。 | 节省 40% 以上的 API 调用开销。 |
| **语义扩散** | 掌握一词，自动降低相关词汇的显示优先级。 | 减少50%的重复解释请求。 |
| **多语种优化** | 根据语种调用对应的词频库和NER模型。 | 提升多语言场景的识别准确率。 |

## 五、 V2.0 开发路线图

1.  **Phase 1 (行为校验)**：实现鼠标轨迹分析和阅读节奏检测，主观判断阅读困惑程度。
2.  **Phase 2 (多语种支持)**：集成FastText，支持中英混合、多语言混合场景。
3.  **Phase 3 (语义关联)**：构建基础语义网络，实现“掌握一词，精通一类”的效果。
4.  **Phase 4 (自适应UI)**：根据难度评分动态调整交互强度，实现真正的无感体验。
5.  **Phase 5 (动态Prompt)**：根据词汇难度和语种，动态调整提示词模板。

---

> **V2.0 结语**：FlowGloss 在 V1.0 的基础上，通过行为数据挖掘、多语种支持和语义关联网络，实现了更智能的触发和更精准的识别。用户无需任何设置，系统就能自动适应不同语言、不同领域的学习场景，成为真正的“认知伴侣”。
